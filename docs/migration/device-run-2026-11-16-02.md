## Exact color semantics

The colors are fixed literals in the probe and DarwinBoot sources.

### Green

`DarwinBootPkg/Driver/Entry.S` paints the top 1/16 with:

```text
0xFF00FF00
```

`DarwinEnter` is called only after `ExitBootServices` returns success.
Therefore green proves:

- EBS succeeded;
- the loader handoff assembly started;
- cache maintenance and `SCTLR_EL1` shutdown were reached as the next steps.

### Magenta

Probe stage 2 paints:

```text
0xFFFF00FF
```

and then re-executes the displaced:

```text
msr SCTLR_EL1, x0
```

The current kernel's patch site is `0xFFFFFFF0073F3350`. Therefore magenta
proves execution reached the instruction immediately before the MMU/cache
enable write.

### Blue

Probe stage 1 paints:

```text
0xFF0000FF
```

at XNU `_start` with `--band 8` (the middle 1/16). Therefore blue proves:

- the branch from `DarwinEnter` to the physical XNU entry succeeded;
- XNU's first entry probe executed with a valid `boot_args` pointer;
- execution continued toward `_start_first_cpu`.

The blue band does not by itself prove post-MMU execution.

## Reset classification

Probe stage 3 is installed at:

```text
0xFFFFFFF0073F3370
```

which is after the verified sequence:

```text
0xFFFFFFF0073F3350  msr SCTLR_EL1, x0
0xFFFFFFF0073F3354  isb
...
0xFFFFFFF0073F3370  stage 3 probe
```

Stage 3 waits six seconds using `cntpct_el0`, then executes PSCI
`SYSTEM_RESET`:

```text
w0 = 0x84000009
smc #0
```

The observed delayed reset and subsequent Android boot are therefore the
intentional probe result, not yet evidence of an unknown watchdog. It proves:

- execution returned from the MMU-enable write;
- post-MMU code reached the stage 3 site;
- the PSCI reset path worked.

The device booted Android because `fastboot boot` is non-persistent and the
installed Android boot partition was not changed.
