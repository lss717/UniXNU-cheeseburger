## Current-path disassembly

`_arm_init` takes the lower-memory path:

```text

0x79BF078  save x28/x27 through x20/x19 and fp/lr
0x79BF090  set fp = sp + 0xC0
0x79BF0B0  BL _arm_set_kernel_tbi       (returns immediately)
0x79BF0BC  read boot_args.MemorySize
0x79BF0C0  TBNZ bit 31 -> large-memory path (not taken for 128 MiB)
0x79BF0C4  scan/relocate boot-args pointer records
```

The path contains no MR/MSR system-register access between `_arm_init` entry
and the `_arm_vm_init` call. MMU/cache state was already established by
`common_start`. The nonzero stack work in this interval is the initial
`0xD0` frame, the saved callee registers, a 0x480-byte boot-args copy, and the
callee frames used by the functions above.

Branches after `0x79BF624` mostly select error paths:

```text
PE_init_platform / DT failures -> Assert or panic paths
invalid boot CPU or max CPU  -> _arm_init+0x9E0
missing boot-arg defaults    -> x19 = 0 path
```

No branch can validly skip the final `BL _arm_vm_init`.
