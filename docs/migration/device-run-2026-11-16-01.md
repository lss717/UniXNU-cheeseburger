## ExitBootServices ordering

In `DarwinBoot.c`, the line:

```text
DARWINBOOT: inputs validated; exiting boot services
```

is written before the large `DARWINBOOT: hand-off to the kernel` DEBUG block
and before the `ExitBootServices` retry loop. It is not a post-success marker.

The green band is different: `DarwinEnter` is called only inside:

```c
Status = gBS->ExitBootServices (mImage, Key);
if (!EFI_ERROR (Status)) {
  ... DarwinEnter (...);
}
```

`DarwinEnter` paints the top 1/16 green before cache maintenance, `SCTLR_EL1`
MMU/cache shutdown, and `br x1`.

Therefore this run proves:

| Checkpoint | Evidence |
| --- | --- |
| Kernel/ADT/video/command-line validation | completed |
| `ExitBootServices` returned success | green band from `DarwinEnter` |
| Reached loader handoff assembly | green band before cache/MMU shutdown |
| Reached XNU first instruction | not yet proven |
| Reached first `SCTLR_EL1` write | not yet proven |
| Reached post-MMU code | not yet proven |

The black panel cannot distinguish an XNU entry failure from a display
handoff failure. It must not be treated as proof that the CPU never executed
the kernel.
