After manual IOS selection the device immediately restarted. This proves:

## Relevant function behavior

`_cpu_data_init` is a bounded zero/initializer store sequence over the CPU-data
block and returns. It performs no system-register access.

`_PE_init_platform(FALSE, boot_args)` sets up:

- platform protection type;
- Secure DT base/length;
- machine identity;
- interrupt initialization path when requested;
- debug path selection.

It contains nested calls and is the largest early candidate in the remaining
range, but the configure-misc reset proves this call returned.

`_configure_timer_apple_regs`, `_configure_misc_apple_boot_args` and
`_configure_misc_apple_regs` are one-instruction `RET` stubs in this kernel.

`_wfe_timeout_configure` parses the boot argument and computes the WFE timeout.
`_wfe_timeout_init` may access:

```text
MRS CNTKCTL_EL1
MSR CNTKCTL_EL1
```

or panic if the computed value is outside the supported range. The
configure-misc reset proves both calls returned.

## Next midpoint: platform stall

The next single point is the entry of `_platform_stall_panic_or_spin`, after:

```text
_configure_misc_apple_boot_args
_configure_misc_apple_regs
_SecureDTLookupEntry
_SecureDTGetProperty
```

This function is especially important because it reads `_reattach_wait`. If
bit 0 is set for the requested mask, it enters a permanent WFE loop after
`paniclog_append_noflush`; the code is:

```text
TST x8, x9
B.EQ return
TBNZ w8, #7 -> cold panic path
BL paniclog_append_noflush
WFE
B WFE
```

An unexpected `_reattach_wait` bit would produce exactly a black hang before
`_thread_bootstrap`, with no synchronous exception.
