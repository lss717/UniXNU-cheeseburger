### Static comparison with the Format 1 main line

The old Format 1 main line reached `_kernel_bootstrap`,
`_kernel_bootstrap_thread`, `_bsd_init` and `IOKitBSDInit`, and used the same
framebuffer geometry:

```text
physical base  0x9D400000
width          1080
height         1920
row bytes      4320
depth          32
```

The H233 experiment read back `0xFF808080` from `0x9D400000`, proving that the
physical framebuffer is both mappable and accessible on this device.

Current DarwinBoot obtains `Video[0]` directly from the GOP
`FrameBufferBase`, with no virtual-address transformation. `PE_init_platform`
copies base/row/width/height/depth into `PE_state.video`; `v_offset` and
`v_length` remain zero. Consequently, the mappings in the current image are:

```text
physical address  boot_vinfo->v_baseAddr & ~3 = 0x9D400000
size              round_page(height * rowBytes) = round_page(0x7E9000)
flags             VM_WIMG_IO
```

The EDK2 platform descriptor is:

```text
Display Reserved  0x9D400000 + 0x02400000
AddMem / MEM_RES / WRITE_THROUGH / MaxMem
```

It is therefore reserved display memory, not conventional RAM. This is
consistent with the physical mapping request.

The old `native-console-enable.patch` only changes
`initialize_screen(kPEAcquireScreen)` from `gc_enable(FALSE)` to re-enabling
the graphics console. It does not affect `ml_io_map_unmappable`, framebuffer
virtual/physical address selection, or `lastVideoVirt`.

The boot-progress patch calls `boot_progress_bind(vinfo.v_baseaddr, ...)` for
custom progress drawing. It does not change `lastVideoVirt`, `newVideoVirt`,
the map size, the memory attributes, or mapping reuse.

The current Format 2 source does not carry `native-console-enable.patch`.
Therefore, after a successful mapping return, ordinary XNU text is not expected
to appear immediately; the frozen UniXNU menu image alone does not prove that
`ml_io_map_unmappable` failed.

The old Format 1 prelink/KVA issue is also not the current stop: this rebuilt
kernel has already reached and returned from `_arm_vm_init`, and has reached the
framebuffer mapping call.
