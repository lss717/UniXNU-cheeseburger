# MSM8998 two-cluster CPU topology fix

## Branch result

The CPU-topology fall-through probe at `0xFFFFFFF0073F572C` went black without
restarting:

```text
boot SHA-256    a75721dbfa8a489c8d8425dda2590416720cc5f3b190b4d5d6cb3149838473a9
VA              0xFFFFFFF0073F572C
source word     0xB0FFEC68
patch word      0x1418E2F1
```

The known-positive `0x5704` checkpoint and negative `0x572C` fall-through put
execution at the `0x5728 B.EQ 0x5920` branch. The target, cold.17, calls:

```text
Assert("phys_cluster_id <= MAX_CPU_CLUSTER_PHY_ID")
machine_routines.c:1099
```

## Root cause

The diagnostic XNU build uses the `BCM2837` board configuration. Its stock
profile declares:

```text
MAX_CPUS          4
MAX_CPU_CLUSTERS  1
MAX_CPU_CLUSTER_PHY_ID = 0
```

The MSM8998 DTS describes a 4+4 CPU layout with `P` CPUs and `E` CPUs in two
different clusters. With `HAS_CLUSTER == 0`, XNU derives:

```text
phys_cluster_id = (cluster_type == CLUSTER_TYPE_P)
```

For a `P` CPU this is `1`, which exceeds the compiled maximum `0`. The compiler
therefore emitted the observed `cluster_type == 2` branch directly to cold.17
and the assertion.

## Source fix

`patches/xnu/msm8998-cpu-topology.patch` changes only the build-target capacity:

```text
MAX_CPUS          4 -> 8
MAX_CPU_CLUSTERS  1 -> 2
```

The patch was applied through `patches/xnu/series`, not by editing a generated
worktree. It dry-ran successfully against the real XNU source before the full
package rebuild.

## Static verification

The old kernel contained:

```text
0xFFFFFFF0073F5720  LDR  w8, [x23, #0x10]
0xFFFFFFF0073F5728  B.EQ 0xFFFFFFF0073F5920   ; assert cold.17
```

The rebuilt kernel instead contains:

```text
0xFFFFFFF0073F5738  LDR  w8, [x24, #0x10]
0xFFFFFFF0073F573C  CMP  w8, #2
0xFFFFFFF0073F5740  CSET w8, EQ
0xFFFFFFF0073F5744  ADD  x9, sp, #0x60
0xFFFFFFF0073F5748  ORR  x8, x9, x8, LSL #3
```

The `P/E` selector now indexes two valid stack slots. It no longer branches to
the `machine_routines.c:1099` assertion.

The package passed:

- 47/47 ADT checks;
- FD/FV module checks;
- boot header and load-range checks;
- manifest validation;
- byte-for-byte comparison between the payload-embedded kernel and candidate
  `kernel.macho`.
